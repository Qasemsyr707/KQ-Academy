# بيئة Staging مستقلة على Coolify

نسخة تجريبية من KQ Academy على الخادم نفسه (Hostinger VPS + Coolify) لا تشارك الإنتاج أي قاعدة
بيانات أو ملفات أو أسرار، ولا ترسل بريداً أو مدفوعات أو صوراً إلى خدمات خارجية. لا يُنفَّذ أي من هذه
الخطوات على تطبيق الإنتاج أو قاعدة بياناته.

## 1. مصدر الكود

- المصدر: **المستودع الخاص** المخصص لـStaging (وليس المستودع العام)، عبر GitHub App في Coolify.
- الفرع: `audit/phase1-notifications-certificates-20261113`. لا يُدمج في `main` في أي مستودع.
- يُحدَّث الفرع في المستودع الخاص فقط، دون تغيير `origin` في نسخة العمل.
- إعدادات التطبيق: Build Pack = **Dockerfile**، المنفذ `3000`، **Auto Deploy = Off**،
  **Preview Deployments = Off**.

## 2. الموارد

| المورد | ملاحظات |
| --- | --- |
| PostgreSQL 17 مستقلة | دون Public Port. لا تُسترجع فيها نسخة من الإنتاج |
| التطبيق | النطاق `https://staging.kqacademy.com` مع HTTPS من Coolify |
| Volume للمستندات | Destination: `/data/kq-documents` |
| Volume لسجلات رفع Bunny | Destination: `/data/bunny-uploads` |

الحاوية تعمل بصلاحية root، فلا حاجة لضبط صلاحيات المجلدين. مسار المستندات يجب أن يكون مطلقاً وخارج
`/app` و`public` ومنفصلاً عن مجلد Bunny وليس رابطاً رمزياً؛ `/data/kq-documents` يحقق ذلك.

## 3. متغيرات البيئة

`NEXT_PUBLIC_*` تُدمج في الكود أثناء البناء: تغييرها في Runtime فقط لا أثر له، وتتطلب Redeploy.
لا تجعل أي سر Buildtime: القيم المتاحة أثناء البناء يمكن قراءتها من طبقات الصورة.

| المتغير | الوظيفة | Buildtime | Runtime | القيمة في Staging |
| --- | --- | --- | --- | --- |
| `NEXT_PUBLIC_APP_URL` | رموز QR، التحقق من مصدر الطلبات، روابط البريد، توفر Stripe | **نعم** | نعم | `https://staging.kqacademy.com` دون مسار |
| `NEXTAUTH_URL` | المصادقة والتحقق من مصدر الطلبات | لا | **نعم** | الأصل نفسه الذي يفتحه المتصفح |
| `NEXTAUTH_SECRET` | توقيع الجلسات ورموز الموبايل | لا | **نعم** | قيمة عشوائية جديدة (`openssl rand -base64 48`) |
| `DATABASE_URL` | قاعدة PostgreSQL | لا | **نعم** | Internal URL لقاعدة Staging فقط |
| `CRON_SECRET` | حماية `/api/cron/reminders` | لا | **نعم** | قيمة عشوائية جديدة، 32 حرفاً على الأقل. دونها لا تعمل المهمة (503) |
| `JWT_SECRET` | مسار تجريبي `mobile/secure-stream` فقط | لا | نعم | قيمة عشوائية جديدة، 32 حرفاً على الأقل. دونها يعيد المسار 503 |
| `DOCUMENT_STORAGE_DIR` | تخزين المستندات الخاصة | لا | **نعم** | `/data/kq-documents` |
| `BUNNY_UPLOAD_STATE_DIR` | سجلات رفع Bunny | لا | **نعم** | `/data/bunny-uploads` |
| `KQ_STAGING` | يسمح بتشغيل سكربت البيانات التجريبية | لا | مؤقتاً | `true`، ثم احذفه بعد التهيئة |
| `KQ_STAGING_SEED_PASSWORD` | كلمة مرور حسابات الاختبار | لا | مؤقتاً | 12 حرفاً على الأقل، ثم احذفه |

### معطّلة في Staging (اتركها غير معرّفة)

| المتغيرات | الأثر عند الغياب |
| --- | --- |
| `IMGBB_API_KEY` | لا رفع خارجي للصور: تُحفظ الصور داخل المنصة. لا يوجد مفتاح احتياطي في الكود |
| `RESEND_API_KEY`, `RESEND_FROM_EMAIL` | لا يُرسل أي بريد ولا يُتصل بمزوّد البريد إطلاقاً |
| `STRIPE_*`, `PAYPAL_*`, `TABBY_*`, `TAMARA_*` | يبقى التحويل اليدوي والمحفظة فقط. Webhooks ترفض الطلبات |
| `BUNNY_LIBRARY_ID`, `BUNNY_API_KEY`, `BUNNY_STREAM_TOKEN_AUTH_KEY` | رفع الفيديو وتشغيله يعيدان 503 برسالة واضحة. لا تستخدم مكتبة الإنتاج أبداً |
| `GEMINI_API_KEY` | المساعد الذكي يعيد رسالة بديلة (Phase 3) |
| `LIVEKIT_API_KEY`, `LIVEKIT_API_SECRET`, `NEXT_PUBLIC_LIVEKIT_URL` | البث المباشر يعيد 503 (Phase 3) |
| `NEXT_PUBLIC_GA_ID` | لا تتبّع، فلا تختلط زيارات Staging بإحصائيات الإنتاج |
| `KQ_HIDE_CURRICULUM` | غيابه = المنهاج مخفي (المطلوب). `false` لاختبار الإظهار، في Buildtime وRuntime |
| `DOCUMENT_LEGACY_STORAGE_DIR`, `KQ_SECURITY_TEST_DATABASE_URL` | غير مطلوبين |

لا تضف `NODE_ENV` أو `PORT`: يضبطهما Dockerfile.

## 4. حماية الوصول (Basic Authentication)

فعّل **HTTP Basic Authentication** من إعدادات التطبيق في Coolify. `noindex` وحده ليس حاجزاً أمنياً.

- يرسل المتصفح بعد إدخال كلمة المرور ترويسة `Authorization: Basic ...` مع كل طلب. التطبيق يتجاهل
  `Basic` (فهي خاصة بالبروكسي) ويستخدم جلسة الويب، مع بقاء التحقق من مصدر الطلب (CSRF) كما هو.
  رموز `Bearer` لتطبيق الموبايل تُعامل كما كانت تماماً.
- اختُبر ذلك محلياً خلف بروكسي يطبق Basic Auth مثل Traefik، في الوضعين:
  - الترويسة تصل إلى التطبيق (الإعداد الافتراضي لـTraefik).
  - `removeHeader=true` يحذف الترويسة بعد التحقق.
  الوضعان يعملان؛ لا حاجة لتغيير إعداد Coolify الافتراضي.
- `removeHeader=true` يحذف أي `Authorization` بعد التحقق، ومنها `Bearer`. تطبيق الموبايل لا يستطيع
  إرسال Basic وBearer معاً أصلاً، فلا يمكن اختبار API الموبايل خلف Basic Auth في أي من الوضعين.
  لاختبار الموبايل لاحقاً: قيّد الوصول بعناوين IP بدل Basic Auth، لفترة الاختبار فقط.

### التحقق من الحماية بعد أول Deploy

```bash
S=https://staging.kqacademy.com
curl -s -o /dev/null -w '%{http_code}\n' $S/                          # 401: كلمة مرور مطلوبة
curl -s -o /dev/null -w '%{http_code}\n' -u 'USER:WRONG' $S/          # 401
curl -s -o /dev/null -w '%{http_code}\n' -u 'USER:PASS' $S/           # 200
curl -s -o /dev/null -w '%{http_code}\n' -u 'USER:PASS' $S/api/notifications             # 401: Basic ليست هوية مستخدم
curl -s -o /dev/null -w '%{http_code}\n' -u 'USER:PASS' -X POST $S/api/cron/reminders    # 401: Basic ليست مفتاح Cron
```

ثم من المتصفح: الدخول بحساب `student-b`، شراء الكورس المدفوع بالمحفظة، ظهور الإشعار، حفظ تقدم درس،
وفتح صفحة الشهادات. أي 401 بعد تسجيل الدخول يعني أن الحماية تتداخل مع التطبيق: أوقف الاختبار وأبلغ.

## 5. تهيئة القاعدة والبيانات التجريبية

بعد أول Deploy، من **Terminal تطبيق Staging** (تحقق من اسم التطبيق قبل الكتابة):

```bash
npx prisma db push --skip-generate     # ينشئ الجداول في قاعدة Staging الفارغة
node scripts/staging-seed.cjs          # حسابات وكورسات تجريبية وشهادة بالصيغة القديمة
```

يرفض السكربت العمل ولا يكتب شيئاً إذا:
- لم يكن `KQ_STAGING=true`.
- كان `NEXTAUTH_URL` أو `NEXT_PUBLIC_APP_URL` نطاق الإنتاج.
- احتوت القاعدة 25 حساباً أو أكثر غير حساباته، أو أي دفعة أو تسجيل أو شهادة لحساب لم ينشئه.

الحسابات على نطاق `kq-staging.invalid` الذي لا يستقبل بريداً. بعد التهيئة احذف `KQ_STAGING` و
`KQ_STAGING_SEED_PASSWORD` من المتغيرات.

## 6. ما يُختبر على Staging

1. **الشهادات على Linux:** اسم عربي وآخر إنجليزي، الخط والمحاذاة، PNG وPDF، رمز QR، التحقق بالرمز
   العشوائي، رفض غير المصرح، منع الإصدار قبل الإتمام، عدم التكرار، والشهادة القديمة `KQ2025-0001`.
   المتوقع للشهادة القديمة (بيانات السكربت): `Course Date: 01/05/2025 - 01/06/2025` و
   `Date of Issued: 01/06/2025`، بهذا الترتيب من اليسار إلى اليمين، في PNG وPDF.
2. التسجيل والدخول والإشعارات، الشراء بالمحفظة والتحويل اليدوي، تقدّم الدروس من جهازين.
3. البحث والفلاتر، إخفاء المنهاج، شريط الشعارات، لوحات الإدارة والمدرّب.
4. حدود الطلبات المفرطة، وحماية Basic Authentication (القسم 4).

## 7. ملاحظات للإنتاج (قبل أي نشر لاحق)

- **`CRON_SECRET`:** بعد هذا الإصدار ترفض المهمة العمل دون مفتاح، وترفض القيمة القديمة المنشورة
  `dev-cron-secret`. تحقق أن المتغير معرّف في الإنتاج بقيمة عشوائية طويلة، وأن أي مهمة مجدولة تستخدمه.
- **`IMGBB_API_KEY`:** المفتاح الذي كان مكتوباً في الكود منشور في تاريخ المستودع العام ويُعد مكشوفاً:
  أبطله من حساب ImgBB وأنشئ مفتاحاً جديداً، وضعه في متغيرات الإنتاج قبل النشر. دون مفتاح تُحفظ الصور
  داخل المنصة بدل ImgBB.
- **`JWT_SECRET`:** يلزم فقط للمسار التجريبي `mobile/secure-stream`؛ لا علاقة له بتسجيل الدخول.
- **البريد:** دون `RESEND_API_KEY` لا يُرسل أي بريد.

## 8. إزالة Staging

احذف تطبيق Staging وقاعدته وVolumes الخاصة به والمستودع الخاص فقط. لا تلمس موارد الإنتاج.
