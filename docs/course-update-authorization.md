# إصلاح أمني: تعديل الكورس عبر `PUT /api/courses/[id]`

الفرع: `security/course-update-allowlist-20261117`، متفرّع من `170d966`، ومستقل عن فرع البحث.

## الخلل

كان المسار يمرّر جسم الطلب كما هو إلى `prisma.course.update({ data: body })`، بعد التحقق من الملكية وحظر العلاقات المتداخلة فقط.

ثبت محلياً عبر HTTP بجلسة مدرّب حقيقية أن المدرّب يستطيع على كورسه:
- جعل `price` و`priceSYP` صفراً.
- منح نفسه `isFeatured` و`rating: 5`.
- تغيير `type` (فيختفي الكورس من الكتالوج أو يظهر فيه).
- **نقل الملكية `instructorId` إلى حساب آخر.**

الواجهة لا ترسل إلى هذا المسار إلا `includes` و`previewVideoUrl`.

## الصلاحيات بعد الإصلاح

| الحقل | المدرّب صاحب الكورس | المدير / المالك | المسار المخصص |
| --- | --- | --- | --- |
| `title`, `description`, `thumbnail`, `includes`, `previewVideoUrl`, `durationHours` | ✓ (بعد التحقق) | ✓ | هذا المسار |
| `categoryId` / `category` / `tags` / `trainingType` (Phase 2) | ✓ (تصنيفات فعّالة فقط، عبر `resolveCourseTaxonomy`) | ✓ | هذا المسار |
| `price`, `priceSYP`, `type`, `isFeatured`, `instructorId`, `status` | ✗ | ✗ هنا | `PUT /api/admin/courses/[id]` (للمدير فقط) |
| الإرسال للمراجعة (مسودة أو مرفوض ← قيد المراجعة) | ✓ | ✓ | `POST /api/courses/[id]/submit` (و`/resubmit` اسم بديل) |
| النشر | ✗ أبداً | ✓ مع سعر صريح | `POST /api/courses/[id]/publish` أو لوحة الإدارة |
| `rating` | ✗ | ✗ | يُحسب من التقييمات |
| `id`, `createdAt`, `updatedAt`، العلاقات | ✗ | ✗ | — |

- أي حقل غير مسموح يُرفض بـ 403 مع اسمه، ولا يُحفظ أي جزء من الطلب.
- الحقول المسموحة يُتحقق منها:
  - الصورة: https، أو مسار داخلي، أو صورة base64 نقطية، أو التدرج الافتراضي.
  - الحدود: الطول، وعدد الميزات، والمدة.
- المالك (`OWNER`) صار له ما للمدير على كورسات غيره، كما في بقية الصلاحيات (`checkRole`).

## حالة الدمج مع Phase 2 (في `feat/phase2.1-20261117`)

تم الدمج: حقول التصنيف تُفصل عن الجسم وتُتحقق بـ `resolveCourseTaxonomy` (بنوع الكورس من القاعدة، لا من الطلب)، وبقية الجسم عبر قائمة السماح؛ أي حقل خارج المجموعتين يرفض الطلب كله قبل أي كتابة. `category` لم يعد نصاً حراً.

## إنشاء الكورس ودورة المراجعة والسعر (بوابة الإصدار، 2026-11-17)

### الخلل
- `POST /api/courses` كان يكتب `status: 'PUBLISHED'` صراحةً، ويأخذ السعر من جسم الطلب، ويحوّل أي سعر غير صالح إلى 0 بصمت.
- `POST /api/mobile/courses` لم يحدد الحالة، فورث قيمة Schema الافتراضية `"PUBLISHED"`.
- النتيجة: المدرّب ينشر كورساً جديداً فوراً، للطلاب وفي البحث وقابلاً للشراء، بالسعر الذي يختاره، دون مراجعة.
- `/publish` كان يسمح للمدرّب بنشر كورسه إن لم يكن مرفوضاً أو قيد المراجعة.
- `PUT /api/admin/courses/[id]` كان يقبل أي نص كحالة، ويحوّل السعر غير الصالح إلى 0.

### السياسة المطبّقة (`src/lib/course-review.ts`)
```
DRAFT ──إرسال──▶ PENDING ──الإدارة──▶ PUBLISHED
                    │  ▲
              الإدارة │ إعادة تقديم
                    ▼  │
                 REJECTED
```
- **المدرّب:**
  - كل كورس جديد ينشئه يبدأ **مسودة `DRAFT`**، من الويب أو الموبايل، أياً كان ما يرسله.
  - يعدّل المحتوى في كل الحالات، ويرسل المسودة أو الكورس المرفوض للمراجعة.
  - **لا ينشر أبداً**: `/publish` يعيد 403 له.
- **السعر:**
  - ما يكتبه المدرّب عند الإنشاء **سعر مقترح**، يُحفظ على الكورس غير المنشور، ولا يمكن الشراء قبل النشر.
  - النشر يتطلب من المدير أو المالك ذكر `price` و`priceSYP` **صراحةً** في الطلب نفسه. لوحة الإدارة ترسلهما دائماً، وتنبّه أن السعر مقترح من المدرّب.
  - السعر الفارغ أو غير الصالح يُرفض (400)، ولا يتحول إلى «مجاني». الصفر الصريح يعني كورساً مجانياً مقصوداً.
  - بعد الإنشاء لا يغيّر المدرّب السعر (قائمة الحقول المسموحة في `PUT`).
- **إنشاء الويب:** أي حقل خارج القائمة (`status`، `instructorId`، `isFeatured`، `rating`، `id`…) يرفض الطلب كله بـ 403.
  - **الموبايل** يتجاهل هذه الحقول كما كان سابقاً، حفاظاً على توافق التطبيق. الحالة والمالك والسعر تُحدَّد من الخادم فقط.
- **المدير والمالك:**
  - يحتفظان بالنشر المباشر عند الإنشاء إذا ذكرا السعرين صراحةً. بدونهما يُنشأ الكورس مسودة.
  - `PUT /api/admin/courses/[id]` يقبل الحالات الأربع فقط.
- **لا تغيير في Schema:**
  - `status` عمود نصي، فقيمة `DRAFT` لا تحتاج ترحيلاً، وكل عرض عام يشترط `PUBLISHED`.
  - القيمة الافتراضية في Schema ما زالت `PUBLISHED`. لذلك يحدد كل مسار إنشاء الحالة صراحةً، واختبار حارس يفشل إن ظهر `course.create` بلا حالة.
  - تغيير القيمة الافتراضية إلى `DRAFT` يحتاج ترحيلاً (`ALTER COLUMN ... SET DEFAULT`)، ويُقترح لاحقاً بقرار منفصل.
- **البيانات القديمة لم تُعدَّل:** الكورسات المنشورة تبقى منشورة بأسعارها، ولا ترحيل بيانات.
