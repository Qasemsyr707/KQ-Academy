# Phase 2: البحث الذكي وتصنيفات الكورسات

الفرع: `feat/search-taxonomy-20261116`، متفرع من `170d966` (نهاية Phase 1 على Staging).

## ما الذي تغيّر

| الجزء | التفاصيل |
| --- | --- |
| البحث الفوري | اقتراحات من أول حرف؛ بادئات الكلمات دون «ال» («تسويق» ← «التسويق الرقمي»)؛ مطابقة داخل الكلمة من 3 أحرف فقط («بر» لا يجد «خبرة»)؛ مرادفات من الأسماء البديلة للتصنيفات والوسوم؛ أخطاء إملائية بسيطة من 4 أحرف؛ حتى 6 كورسات و4 أقسام |
| مصدر الاقتراحات | الكورسات المنشورة والمعروضة للعامة فقط، والتصنيفات التي تحتوي كورساً منها فعلاً. لا نصوص ثابتة |
| الواجهة | `SearchCombobox`: صورة، اسم، تصنيف، سعر؛ أسهم/Enter/Escape؛ ARIA combobox؛ debounce ‏200ms مع إلغاء الطلب القديم وعدم عرض نتائج نص سابق |
| التصنيفات | جدول `Category` بمستويين (24 رئيسياً + 116 فرعياً)، أسماء بديلة، تفعيل/إيقاف، ترتيب. خيار النموذج القديم «الفنون والموسيقى» صار تصنيفاً فرعياً باسمه نفسه تحت «المهارات المهنية والحرفية»، فتُربط كورساته تلقائياً |
| الكورس | `categoryId` (اختياري)، `tags`، `trainingType`؛ النص `category` باقٍ ويُملأ باسم التصنيف |
| الإدارة | `/admin/categories` للمدير والمالك فقط؛ منع التكرار بالاسم المطبَّع وبالـ slug؛ لا حذف لتصنيف مرتبط |
| النماذج | إنشاء الكورس، وزر «التصنيف والوسوم» في صفحة إدارة محتوى الكورس |

## خطوات النشر على Staging (بعد الموافقة فقط)

قاعدة البيانات أولاً، ثم الكود. الكود القديم (`170d966`) يعمل مع الأعمدة الجديدة، والكود الجديد **لا يعمل** قبلها.

1. نسخة احتياطية من قاعدة `kqacademy_staging`.
2. قراءة فقط: `prisma/manual-migrations/00_preflight_phase2_taxonomy_readonly.sql`، وراجع عمود `result`:
   - `mapped_to`: سيُربط بالتصنيف المذكور.
   - `unmapped`: يبقى بنصه، ويظهر في البحث والفلاتر كما هو.
   - `ambiguous`: لن يُربط.
3. `prisma/manual-migrations/20261116_phase2_course_taxonomy.sql` (آمن للتكرار).
4. Redeploy من الفرع. لا `prisma db push` ولا Seed.

## التراجع

| ما الذي فشل | ماذا يحدث | ماذا تفعل |
| --- | --- | --- |
| الترحيل نفسه (مثلاً انتهاء `lock_timeout` بسبب ازدحام) | الملف كله معاملة واحدة: لا يُطبَّق منه شيء | أعد تشغيله في وقت أهدأ؛ آمن للتكرار |
| النشر بعد نجاح الترحيل | الكود السابق يعمل مع الأعمدة الجديدة (مُختبر: اختبارات PostgreSQL لـ `170d966` على قاعدة مُرحَّلة 9/9) | Redeploy للنسخة السابقة `170d966` في Coolify؛ لا تشغّل DOWN |
| التخلي النهائي عن المرحلة | — | `prisma/manual-migrations/rollback/20261116_phase2_course_taxonomy_DOWN.sql` بعد نسخة احتياطية. يحذف التصنيفات والروابط والوسوم، ولا يمس نص `category` ولا أي كورس |

لا تنشر الكود الجديد قبل الترحيل: سيفشل تحميل الكتالوج لأن عمود `categoryId` غير موجود.

## ما تم التحقق منه محلياً على PostgreSQL معزول

- قاعدة بمخطط `170d966` وبيانات قديمة اصطناعية، ثم:
  1. الفحص التمهيدي (preflight).
  2. تطبيق UP مرتين.
  3. `prisma migrate diff` أعاد نتيجة فارغة، أي أن المخطط مطابق للـ Schema الجديد.
  4. DOWN، ثم `migrate diff` أعاد نتيجة فارغة أمام المخطط القديم.
  5. UP مرة أخرى.
- الـ Backfill لا يغيّر النص ولا `updatedAt`، ولا يعيد ربط كورس مرتبط، ولا يتغيّر شيء بتشغيله مرتين.
- التطبيع في SQL مطابق للتطبيع في التطبيق.

## إضافة تصنيف لاحقاً

من `/admin/categories`، دون تعديل كود. لتغيير القائمة الافتراضية نفسها، عدّل `prisma/taxonomy/categories.json` ثم شغّل:

```
node scripts/generate-taxonomy-sql.cjs
```

يفشل اختبار `search-taxonomy` إذا لم تُولَّد ملفات SQL من جديد بعد تعديل القائمة.
